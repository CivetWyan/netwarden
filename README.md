# 网络修复大师（netwarden）

面向**小米路由器**小型网络（工作室、小办公室）的本地 AI 网络自愈工具。它常驻在局域网里的一台电脑上，持续探测网络；断网时在几秒内定位故障出在哪一层，由**本地小模型**挑选修复动作，通过路由器管理接口或本机网络命令执行，并用连续探针验证结果。网络恢复后，再请**在线大模型**复盘这次故障，把经验沉淀成可复用的修复方案：同类故障下次再出现时直接执行，不必再问模型。

- 断网时不依赖外网：诊断、决策和修复全部在本地完成（本地模型 + 本地知识检索）。
- 修复动作全部白名单化，每次修改前快照、修改后读回校验、未通过验证自动回滚。
- 在线复盘只在恢复后进行，只上传脱敏后的故障证据。

## 实现了什么

| 能力 | 说明 |
|---|---|
| 持续感知 | 默认每 1.5 秒并行探测网卡、路由、网关、多个外网 TCP 目标、DNS（含绕过缓存的随机域名探针）、HTTP；同时读取路由器 WAN 状态。连续两次失败才判定断网，避免瞬时抖动误报 |
| 分层分诊 | 确定性规则在约 2 秒内判断故障层级：本机 → 本机到路由器 → **路由器 WAN 配置是否偏离健康基线** → WAN 链路/拨号 → 上游网关 → DNS → 上级网络疑似封禁。输出固定词表的"信号"和按代价排序的候选动作 |
| 本地模型快速决策 | 本地小模型（实测 Qwen3.5-9B Q4_K_M）只做一道选择题：从规则筛出的 2–4 个候选里选一个，多次采样投票取多数。选了不在候选里的动作算废票；模型不可用时由规则兜底 |
| 路由器控制 | 封装小米路由器管理 API（登录、令牌续期、读回校验、接口白名单）：恢复 WAN 配置到健康基线、按当前配置重连 WAN、更换 WAN 的 MAC/IP、重启路由器（最后手段）。见 [docs/xiaomi-router.md](docs/xiaomi-router.md) |
| 安全执行 | 每个修改动作：动作前重新采集现场 → 持久化回滚事务 → 执行 → 读回确认 → 连续探针验证 → 失败自动写回动作前配置。每次故障有动作预算，同一动作不重复；重启路由器被规则护栏限定为最后手段 |
| 健康基线 | 自动记录路由器 WAN 健康配置。新配置必须连续健康一段时间（默认 10 分钟）才会成为新基线，刚改坏的配置不会覆盖基线 |
| 上级网络封禁处理（默认关闭） | 用于上级网络（如园区网）按 IP/MAC 封禁、且**网络运营方允许以更换 IP/MAC 恢复接入**的环境：用同网段已知邻居判断"是只有本机被挡、还是整段断网"；换 IP 前先 ping 确认没人占用，换后验证不通就自动换回原 IP 和 MAC |
| 在线复盘与自我提升 | 恢复后把脱敏的分诊结果、每一步决策和投票、执行与验证日志交给在线模型（如 DeepSeek）。在线模型给出根因、对本地模型决策的评价、写给小模型的经验，以及声明式修复方案（信号 → 白名单动作序列）。方案先作为候选，在真实故障里验证成功后自动启用；多次失败自动停用 |
| 智能体兜底 | 快速修复未成功时，本地模型进入工具循环继续调查（读日志、查路由器状态、指定服务器的 DNS 查询、HTTP 检查、离线知识检索、子任务、计划与目标检查、上下文压缩与会话续跑），并如实报告无法自动处理的原因 |
| 网页与桌面界面 | 局域网网页（带登录、Host/Origin 校验、来源网段限制）和 Electron 桌面版：运行总览、成就计数（连续健康时长、自愈次数、未修复次数、成功率、累计流量）、路由器 WAN 与身份、AI 对话、经验与方案、日志、设置 |
| 离线知识 | 可选导入自备的网络原理资料和设备手册，CPU BM25 检索，不占显存。仓库不附带知识数据，见 [knowledge/README.md](knowledge/README.md) |

## 效果

在一台小米 BE6500 路由器 + 局域网 Linux 服务器（本地模型跑在一张 RTX 5090 上）上，向真实路由器注入故障的实测结果：

| 注入的故障 | 网管表现 | 从注入到恢复 |
|---|---|---|
| WAN 网关被改错（第 1 次） | 分诊发现配置漂移，本地模型 0.6 秒选出"恢复基线"，一次修好；在线复盘生成候选方案 | 10.6 秒 |
| 同类故障第 2 次 | 匹配到候选方案，模型同样选对；方案在真实故障中验证通过，转为启用 | 13.3 秒 |
| 同类故障第 3 次 | **直接执行已启用方案，不再调用模型** | 8.1 秒 |
| WAN 口速率被强制成上级不支持的值（链路断开） | 识别出速率配置漂移，写回自动协商 | 配置 10.8 秒恢复；链路重新协商后约 39 秒恢复上网 |

- 从故障发生到确认断网约 4.5 秒，分诊约 2 秒，本地模型每次决策 0.5–0.8 秒。
- 更换 WAN 的 MAC + 同网段空闲 IP 并验证、再换回原值，每一步约 5 秒（在真实路由器上验证了机制，没有真实的封禁场景可测）。
- 单元与集成测试 113 项（`npm test`），覆盖路由器协议与白名单、分诊、投票与规则护栏、读回与回滚、方案学习、封禁识别、统计口径、网页认证等。

## 工作原理

```
探针（本机 + 路由器）──► 连续两次失败确认断网
        │
        ▼
分层分诊（规则，约 2 秒）──► 层级 + 信号 + 按代价排序的候选动作
        │
        ├─ 有已启用方案 ──► 直接按方案执行
        ├─ 否则 ──► 本地模型投票选一个候选（选错/不可用时规则兜底；重启路由器有护栏）
        ▼
执行：快照 → 写入 → 读回 → 连续探针验证 → 未通过则回滚 → 重新分诊（受动作预算限制）
        │
        ├─ 修好 ──► 记录自愈；恢复后进入在线复盘队列
        └─ 没修好 ──► 本地模型工具循环继续调查，如实报告
                                 │
在线复盘（恢复后）──► 根因 / 经验 / 声明式方案（候选）──► 真实故障验证 ──► 启用 ──► 下次直接复用
```

设计取舍：

- **小模型只做选择题，不读文档写代码。** 路由器协议细节（登录算法、nonce 规则、写后读回、哪些接口危险）全部固化在代码里。本地 9B 模型面对的是 2–4 个说明清楚的候选动作，速度快、出错面小。
- **证据分层，不让模型自说自话。** TCP 端口可达不等于网页可打开，网页可打开不等于已登录或已改配置，命令返回成功不等于网络恢复。只有连续健康探针能证明恢复。
- **在线模型产出的是声明式方案，不是脚本。** 方案只能引用固定词表里的信号和白名单动作，而且匹配信号必须在源故障中实际出现过；引擎可以直接执行和验证，不需要开放任意脚本执行权限。

## 快速开始

### 后台服务（Linux，推荐）

需要 Node.js 22+（实测 24）。后台服务只用 Node 内置模块，无需 `npm install`。

```sh
git clone https://github.com/CivetWyan/netwarden.git ~/netwarden && cd ~/netwarden
mkdir -p runtime-service && cp deploy/config.example.json runtime-service/config.json
cp deploy/model.env.example deploy/model.env && chmod 600 deploy/model.env
# 编辑 runtime-service/config.json（本地模型地址、路由器地址）和 deploy/model.env（路由器密码等）
NETWORK_REPAIR_HOME=$PWD/runtime-service node src/daemon.mjs --once   # 单次探测，检查配置
```

安装为用户级 systemd 服务、配置本地模型、打开网页等完整步骤见 [deploy/README.md](deploy/README.md)。

### 桌面版（macOS / Windows / Linux）

```sh
npm ci
npm run prepare:electron
npm start
```

也可双击 `启动.command`（macOS）、`启动.bat`（Windows）、`./启动.sh`（Linux）。关闭窗口后驻留托盘，从托盘菜单退出才停止。不要让桌面版和后台服务同时管理同一台主机。

### 模型

本地与在线模型都使用 OpenAI Chat Completions 兼容接口，`baseUrl` 可填 `.../v1` 或完整的 `/chat/completions` 地址：

- 本地：Ollama、LM Studio、vLLM 等。推荐 Qwen3.5-9B 的 GGUF Q4_K_M 量化版，约占 6 GB 显存。不支持原生工具调用的模型可以切换到 JSON 工具模式。
- 在线复盘：默认 DeepSeek（`https://api.deepseek.com/v1`），也可以换成其他兼容服务。没有在线模型时，本地诊断和修复照常工作，只是不复盘。

两个模型配置互相独立：本地模型不可用时，故障处理**不会**悄悄转交云端。

## 主要配置

运行数据目录由 `NETWORK_REPAIR_HOME` 指定（默认项目内 `runtime/`），配置为其中的 `config.json`，完整字段和取值范围见 `src/store.mjs` 的 `defaults` 与 `validateConfig`。

| 字段 | 默认 | 说明 |
|---|---|---|
| `repair.enabled` | `false` | 自动修复总开关；关闭时只诊断、给建议 |
| `repair.fastDecision` / `repair.votes` | `true` / `3` | 本地模型快速决策及投票次数 |
| `repair.maxActions` | `4` | 每次故障最多尝试的动作数 |
| `router.enabled` / `router.host` | `false` / 空 | 启用小米路由器管理及管理地址 |
| `router.allowRestore` / `allowReconnect` / `allowReboot` | `true` | 路由器各动作的授权 |
| `router.allowIdentityChange` | `false` | 更换 WAN 的 MAC/IP（仅在运营方允许时启用） |
| `router.identityIps` | `[]` | 更换身份时优先使用的同网段备用 IP |
| `review.enabled` / `review.upload` | `false` / `confirm` | 在线复盘；`auto` 为恢复后自动上传脱敏包 |
| `scripts.enabled` | `false` | 允许模型执行临时脚本（见下文，风险较高） |
| `monitor.tcpTargets` / `dnsHosts` / `dnsCanary` | 公共 DNS 等 | 探测目标；应选本地网络正常时确实可达的目标 |

凭据只通过环境变量（`NETWORK_MODEL_API_KEY`、`NETWORK_ONLINE_API_KEY`、`NETWORK_ROUTER_PASSWORD`）或运行目录里权限为 600 的密钥文件提供，不写入 `config.json`。日志、任务记录和导出报告会对已配置的密钥及路由器返回的明文密码字段脱敏。

## 平台支持

| 能力 | Linux | macOS | Windows |
|---|---|---|---|
| 探测与分诊 | ✅ NetworkManager / iproute2 / systemd-resolved | ✅ | ✅ PowerShell |
| 路由器动作 | ✅ | ✅ | ✅ |

| 实测程度 | 后台服务在 Ubuntu 上实测 | 桌面版实测 | 未在实机验证 |

## 临时脚本（默认关闭）

模型可以用 `create_script` 编写 Node/Python/Shell/PowerShell 脚本，再用 `run_script` 执行。执行需要**同时开启自动修复和脚本开关**。源码不可变（改一个字符就是新版本、新哈希），执行账本记录 PID、退出码、输出和前后探针结果，同一故障里的相同脚本不会重放，异常退出后结果未知的调用不会被自动重放。

这是当前用户权限下的任意代码执行能力，**没有文件系统或网络沙箱**。以 root 运行服务时，脚本也具有 root 权限。只在理解风险后开启。

## 数据文件

运行目录中的主要文件：

- `config.json`：公开配置；`secret.json`、`online-secret.json`、`router-secret.json`：凭据；`web-access.json`：网页访问密码。
- `events.jsonl`：现场、分诊、决策、动作、验证日志（约 5 MB 轮转）。
- `router-baseline.json`、`identity.json`：路由器 WAN 健康基线；身份轮换的参照邻居与疑似被封记录。
- `playbooks.json`、`memory.json`、`reviews/`：学到的修复方案、经验与脱敏复盘包。
- `stats.json`：成就计数（连续健康、自愈、未修复、流量）。
- `transcripts/`、`sessions/`：模型原始消息与可续跑检查点。

## 已知限制

- 只能修复"路由器配置被改坏""WAN 掉线可重连"一类问题。网线、光猫、运营商故障，路由器死机，以及部署网管的这台电脑自己连不上路由器，都只能如实报告。
- 网管只从部署它的那台电脑的视角探测，发现不了只影响其他设备的问题。
- 静态 IP 场景实测较多；PPPoE、DHCP 上网方式和路由器重启路径只有单元测试。
- 路由器 API 在 BE6500 上实测，其他小米型号需要先只读验证。
